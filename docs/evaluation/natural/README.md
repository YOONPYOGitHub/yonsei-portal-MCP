# 대충 물어보는 한국어 대화 평가

기존 152개 질문은 기능 계약을 확인하는 문장입니다. 이 묶음은 줄임말·생략·되묻기·대상 변경이 있는 대화를 별도로 확인합니다. **모델이 작성한 구어체 합성 질문**이며 실제 사용자의 대화 로그가 아닙니다.

- [질문 읽기](QUESTIONS.md): 독립 대화 10개, 대화마다 사용자 발화 4개
- [모델 입력](prompts.jsonl): ID·대화 ID·순서·사용자 문장만 포함
- [검토 기준](rubric.jsonl): 허용되는 응답 유형·확인 조건·금지 주장. 답변 모델에 먼저 주지 않음

## 실행 방법

1. 대화마다 새 모델 문맥을 사용합니다. 알려진 사용자 소속과 읽기 전용 범위, 실제 `tools/list` 메타데이터는 제공할 수 있습니다. 정답 도구 경로·평가 기준·기존 답변은 제공하지 않습니다.
2. 현재 사용자 발화 하나만 전달합니다. 다음 발화는 현재 답변을 저장한 후 공개합니다. 앞선 사용자 문장과 **실제로 생성된 답변**을 후속 문맥에 넣습니다. 예시 답변이나 가상의 목록을 넣지 않습니다.
3. 모델이 조회 여부·도구·인자를 선택합니다. 질문이 충분하면 조회하고, 대상이 없거나 모호하면 확인하거나 한계를 설명합니다. 모든 질문을 억지로 도구 호출로 연결하지 않습니다.
4. 실제 MCP 응답·오류·시각·선택한 인자와 답변을 비공개로 저장합니다. 계정 조회는 순차 실행합니다. 같은 대화의 앞선 실제 응답을 재사용할 수 있지만 다른 대화의 근거를 몰래 섞지 않습니다.
5. 답변이 저장된 뒤 독립 검토자가 질문·실제 앞선 대화·응답·`rubric.jsonl`을 비교합니다. 여러 합리적 도구 경로를 인정하고, 올바른 되묻기/거절을 조회 실패로 채점하지 않습니다.
6. 확인된 문제는 원문을 보존한 채 별도 수정본 또는 재실행으로 검증합니다. 파서 결함은 실패를 재현하는 테스트부터 추가합니다. 답변 표현 오류와 서버 결함, 잘못된 평가 기준을 구분합니다.

`tests/qa/natural.py`의 `turn_packet()`은 현재 발화와 중립적인 문맥만 담습니다. 입력에 평가용 필드가 섞이면 제거해서 숨기는 대신 오류로 거절합니다. `validate_dialogues()`와 `validate_readable_dialogues()`는 ID·대화 순서·기준 대응과 읽기용 문서의 일치를 검사합니다. `validate_trace()`는 저장된 사용자 문장, 응답 상태, 같은 대화의 과거/현재 근거 참조와 해시, 발화 공개 순서, 중복 없는 호출 시작/종료 및 직렬화를 확인합니다. 내용의 정확성은 별도 검토가 필요합니다. 이 함수들은 모델이나 학교에 접속하지 않습니다.

## 이번 평가의 분리 범위

현재 대화 모델과 같은 모델의 별도 문맥에서 대화별 답변을 생성합니다. 실행 중에는 평가 기준과 미래 발화를 전달하지 않고, 순서 제어와 실제 호출 기록을 검사합니다. 이는 **절차적으로 입력을 분리한 보조 평가**입니다. OS 차원의 비밀 파일 격리나 모델 학습 데이터의 독립성을 증명하는 보안 샌드박스는 아닙니다.

검토 전 질문·평가 기준의 해시를 남깁니다. 기준이 부당하거나 문맥상 다른 해석이 타당하면 근거를 기록하고 새 버전으로 재검토합니다. 최초 기준과 실패를 지워서 통과로 바꾸지 않습니다.

## 결과 해석과 보관

- 실제 조회 답변, 문맥에 근거한 답변, 확인 질문, 안전 거절, 대상 부재, 도구 오류를 구분합니다.
- “그거”, “첫 번째”는 모델이 실제로 보여준 항목을 기준으로 판단합니다. 앞서 목록을 제공하지 않았으면 임의의 첫 항목을 고르지 않습니다.
- 기간·소속·대상이 바뀌면 이전 조건을 그대로 쓰지 않습니다. 반대로 후속 발화가 조건을 취소하지 않았다면 앞서 정한 조건을 유지합니다.
- 빈 결과·미공개·날짜 해석 실패는 0점·일정 없음·신청 가능으로 바꾸지 않습니다.
- 예약·신청·제출·연장·업로드는 실행하지 않습니다. 이 묶음은 기존 읽기 전용 MCP의 사용성을 평가하며 새 쓰기 기능을 요구하지 않습니다.
- 질문 40개를 처리했다고 MCP를 40회 호출했거나 도구 38개를 모두 검증한 것은 아닙니다. 호출 수·응답 유형·상황별 실패를 별도로 셉니다.
- 개인 답변과 원문은 저장소 밖 전용 폴더에 보관합니다. 공개 저장소에는 질문·검토 기준·검증 코드만 넣습니다. `verify_full_archive()`로 전체 내보내기 파일의 누락·추가·변조를 확인할 수 있지만, 체크섬은 답변의 정확성이나 원격 실행의 진실성을 증명하지 않습니다.

이 소규모 합성 묶음에서 잘 답했다는 이유로 실제 사용자 전체의 질문을 잘 처리한다고 일반화하지 않습니다. 검토 결과를 보고 새로운 실제 사용 사례를 추가합니다.
